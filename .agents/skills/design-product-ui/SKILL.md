# Проектирование Product UI

Проектировать интерфейс от задачи пользователя и контента. Использовать существующие MUI theme overrides, palette и SCSS Modules.

## Определить сценарий

- Кто пользователь и какую задачу он завершает.
- Откуда он приходит и куда должен попасть.
- Главное и вспомогательные действия.
- Какая информация нужна до действия.
- Что сохраняется в URL или после возврата назад.

Для каталога приоритизировать обнаружение контента, сравнение вариантов и быстрый переход к карточке фильма.

## Построить карту состояний

- initial/loading;
- progressive loading;
- empty из-за отсутствия данных;
- no results из-за фильтров;
- recoverable error с повтором;
- success;
- частичные данные, отсутствующий постер и длинный текст.

Не объединять «нет данных» и «ошибка».

## Задать иерархию

1. Определить один визуально главный элемент страницы.
2. Сгруппировать связанные управление и результат.
3. Расположить частые действия ближе редких.
4. Сохранить читаемый порядок DOM без зависимости от desktop-сетки.
5. Использовать disclosure для второстепенных фильтров на малых экранах.

Проверить Header, MovieFilters, GridGallerySct, SimpleCart и MUI theme overrides до добавления нового паттерна.

## Спроектировать responsive-поведение

Начать с узкого экрана. Для каждого breakpoint определить изменение навигации, фильтров, колонок, порядка контента, sticky-элементов, overflow и touch targets.

Не скрывать необходимую функцию на mobile без доступной альтернативы.

## Проверить доступность

- Использовать нативный семантический элемент до ARIA.
- Обеспечить label, accessible name и понятный текст ошибок.
- Сохранить логичный tab order и видимый focus.
- Не кодировать смысл только цветом.
- Проверить contrast, hover, focus и disabled.
- Учитывать `prefers-reduced-motion`.
- Давать изображениям содержательный alt либо пустой alt для декора.

Для подробной проверки прочитать [ui-review-checklist.md](references/ui-review-checklist.md).

## Передать brief

Вернуть цель и flow, информационную иерархию, состояния, responsive-правила, переиспользуемые компоненты, ключи переводов и проверяемые acceptance criteria.
